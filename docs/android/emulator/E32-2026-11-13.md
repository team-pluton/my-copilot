## 이번 실행에서 찾아 고친 것 (화면 · 문구 — 판단 규칙은 그대로)

1. **추천이 사라지면 '이미 내비에 보낸 경로' 표시도 사라졌다** — 다시 판단에서 추천이 없을 때 승인한 곳 · 내비 확인 문장이 화면에서 빠져, 경로가 바뀐 것처럼 보일 수 있었다(실제 내비는 그대로). → 추천 유무와 상관없이 보여 준다(ArriveCard).
2. **대안이 없을 때 이유가 안 보였다** → "제외 · 서울글로벌센터 공영주차장(시) · 도착 예정 시각에 운영하지 않아요"를 보여 준다(거리 밖은 너무 많아 뺀다).
3. **정보를 못 받은 것을 '바뀌었어요'라고 말했다**(D7 과 같은 종류) — "안내 중인 주차장이 바뀌었어요 · 주차장 정보를 확인하지 못했어요" → "주차장 정보를 확인하지 못했어요 · 안내 중인 경로는 그대로예요". 실제 변화는 "안내 중인 주차장 · 만차로 표시돼 있어요". TS ↔ Kotlin 거울 · 테스트 갱신(TS 234 · Kotlin 288 통과).
4. **조회 실패 시각을 '마지막 확인'으로 썼다** → 실패면 "마지막 시도 HH:mm · 정보를 다 받지 못했어요".

1. "다른 적합 후보 · 세종로 · 도착 후 남는 시간이 동국제강보다 약 **-6분** 많아요" — 가까운 후보 우선으로 앞선 후보를 여유가 더 큰 후보와 비교해 음수 문장을 만들었다(`decisiveReason` · 앞선 쪽이 그 기준에서 실제로 나을 때만 이유로 말하게, TS ↔ Kotlin · 회귀 테스트). 그 줄은 비교 대신 거리 · 소요 시간 사실만.
2. 승인 없이 목표만 복원할 때 내비 연결 전에 판단해 '내비 소요 시간을 받지 못해 판단을 보류해요'로 시작했다 → 내비 연결을 기다린 뒤 판단(7초).
3. 운전자가 내비를 바꾼 뒤 다음 3분 확인까지 '안내 중'을 그대로 말했다 → 앱 창으로 돌아올 때 내비 목적지만 다시 읽는다.
4. 만차 이유가 주 문장 · 설명 · 알림에 세 번 반복 → 경로가 설정된 뒤 알림은 버튼만.

남은 것: 결과를 바꾸는 실데이터 변화(아직 못 봄) · 사용자 조작 감소 측정(설계 `docs/my-copilot/v7/USABILITY-TEST-PLAN.md`, 11/27~12/2) · 주행 중(제한) 화면에서의 알림 보류는 에뮬레이터에 속도 신호가 없어 단위 동작만.

## 남은 한계 (주장하지 않는 것)

- ~~승인 · 실행 상태는 앱 프로세스 안에만 있다~~ → 목표와 내비에서 확인된 승인을 저장하고, 다시 열면 내비를 다시 읽어 같을 때만 되살린다(위 표). 약속 시각이 지나면 버린다.
- 후보별 소요 시간은 **현재 위치 기준 내비 예상**이다 — 실시간 교통 반영 여부는 미확인(`trafficConditions` 구간 정보는 온다).
- 에뮬레이터 현위치는 성남 수정구로 고정 — 광화문까지 약 27km.
- 주차 정보는 서울 시영 주차장만(공공 API). 빈자리는 '표시'일 뿐 도착 때 있는지는 모른다 — 화면에 그렇게 쓴다.
- 경로 설정 ≠ 주차 · 방문 완료. 앱은 주차 · 방문을 기록하지 않는다.
