## 0. 중심 문장과 정정

**MY CO-PILOT — 여러 서비스의 정보를 연결하고, 운전자에게 필요한 다음 행동을 하나의 결정으로 제안하는 지능형 차량용 통합 어시스턴트.**

- 쉼표 DRIVE → MY CO-PILOT 전환의 이유는 **EV 충전 판단을 고도화하는 것이 아니다.** 여러 앱과 서비스를 통합하고, 운전자의 상황에 맞춰 다음 행동을 지원하는 차량용 플랫폼을 만드는 것이다.
- **EV 충전 판단은 정체성이 아니다.** 통합 의사결정 기술을 검증하는 **첫 번째 사용 사례**다.
- **MY CO-PILOT 은 충전소 추천 앱이 아니다.**

## 3. 런처가 아니다 — Workflow Integration

예상 질문: "여러 앱을 모아 놓은 런처 아닌가요?"

**답**: 앱을 모으는 것이 아니라 **일을 묶는다.** 운전자가 여러 앱을 차례로 열어 비교하던 과정을, 결과 하나와 승인 하나로 바꾼다.

| 상황 | 지금 운전자가 하는 일 | MY CO-PILOT | 상태 |
|---|---|---|---|
| **아이 픽업 후 귀가** | 차량 설정에서 시트·공조를 따로 → 내비에 학원 → 대기 중 귀가 경로를 다시 검색·설정 | 목적 한 번 선택 → 지금 설정과 다른 것만 승인 한 번 → 학원 도착 뒤에도 귀가를 기억 → 대기 중 "집으로 안내 시작" 한 번 | **[에뮬]** E21·E22·E23 (도착 전환은 모의 주행) |
| **가족 장거리 (EV)** | 잔량 확인 → 충전 앱 → 휴게소 검색 → 시설 확인 → 내비 경유지 | 도착 후 대기까지 센 에너지 → 충전기 상태·동승자 조건으로 결정 하나 → 승인 → 내비 경유지 → 재조회 | **[에뮬]** 차량·내비 · **[실 API]** 충전소(연결표 검수 전) |
| 업무 미팅 | 일정 확인 → 지도 검색 → 주차장 검색 → 내비 설정 | 일정·교통·주차를 묶어 방문 계획 하나 | **[미구현]** |
| 가족 외출 | 장소 검색 → 영업 확인 → 주차 확인 → 경로 | 방문 가능한 곳 + 주차·이동 조건을 함께 비교해 하나 | **[미구현]** |
| 갑작스러운 일정 변경 | 여러 앱에서 다시 확인 | 바뀐 조건으로 다시 판단 | 부분 — 차량 값 변화 재판단 · Mission 복원 **[에뮬]**, 외부 일정 변화 **[미구현]** |

조작 단계·시간이 얼마나 줄었는지는 **측정 전이다.** 사용자 평가 0명이므로 숫자를 쓰지 않는다.

## 4. 다섯 질문에 대한 답

### Q1. 기존 현대차 앱 · Gleo AI 와 무엇이 다른가

| 대상 | 무엇을 하나 (근거) | MY CO-PILOT 과의 관계 |
|---|---|---|
| 기본 내비 | 목적지·경유지 2개·재탐색 [문서·에뮬] · 도착 잔량 예측·충전 계획 [AAR] | **대체하지 않는다.** 경유지를 *왜 거기로* 넣는지 결정하고, 실행은 내비 API 로 한다 |
| 차량 설정 앱 | 시트 프리셋 1·2 · 사전 공조 스케줄 · 충전 목표 · 캠핑 모드 [에뮬 이미지 13절] | 기능은 이미 있다. 우리는 **누구와 어디로 왜 가는지**에 맞춰 그 기능들의 조합을 고르고, 다른 것만 한 번에 승인받는다 |
| 마이현대 | 원격 제어·정비·주변 검색 [전해 들음] | 영역이 다르다(차 밖 · 소유 주기). 원격 준비는 경계만 둔다(`RemotePrepareGateway`) |
| Gleo AI | 호출하면 대화로 답하는 음성 비서 [상태바 구성 확인] · 경로상 장소 검색 [전해 들음] | **묻기 전에** 차량 상태와 이동 목적으로 다음 행동 하나를 고르고, 실행한 뒤 결과를 확인한다. 범용 대화·검색은 만들지 않는다. 음성 입구를 Gleo 에 맡기는 연계는 Gleo Interface 등록 조건이 **미확정** |

정리하면: 현대차의 기능들은 **각각 잘 동작하는 도구**다. MY CO-PILOT 은 그 도구들을 이번 이동에 맞는 **순서와 조합으로 엮는 층**이다.

### Q2. 여러 앱을 쓰는 불편을 구체적으로 어떻게 줄이나

1. **한 번 고르면 다시 묻지 않는다.** 목적(픽업 후 귀가)과 탑승 조합(엄마 + 아이)을 한 번 고르면, 실내 준비 · 대기 · 귀가 안내가 그 선택을 다시 쓴다.
2. **다른 것만 묻는다.** 저장된 취향과 지금 차량 설정을 자동으로 비교해서, 바꿀 것만 승인 하나로 묶는다.
3. **다음 단계를 기억한다.** 도착은 완료가 아니다. 대기 중에 귀가를 묻고, 승인하면 내비 안내를 시작한다. 앱이 꺼졌다 켜져도 이어진다.
4. **비교는 앱이 하고, 결과 하나만 보여 준다.** EV 장거리에서는 에너지 · 충전기 상태 · 동승자 시설을 함께 걸러 추천 하나와 대안 둘만 보여 준다.
5. **실행 결과를 확인한다.** "요청함"이 아니라 "반영됨"을 다시 읽어서 보여 준다. 운전자가 다른 앱으로 확인하러 가지 않아도 된다.

### Q3. 전기차가 아닌 차량에서도 쓸 이유

**지금 동력원과 무관하게 동작하는 것**:
- 탑승 조합별 실내 준비(공조·시트 — HVAC·Seat 도메인은 EV 전용이 아니다)
- 이동 목적 Mission(픽업·귀가 기억 · 원탭 귀가 안내)
- 출발 준비 · 하차 확인
- 제안 하나 · Safety Gate

에뮬레이터 실측은 EV 이미지에서 했다. 내연기관 차량에서 같은 신호가 오는지는 **미확인**이다.

**에너지**: EV 판단만 있다. 연료 계산은 **지원하지 않는다**(SDK 데이터 확인 전). 비EV 차량에서는 에너지 기능만 끄고 나머지는 그대로 동작한다. 동력원을 모르면 공통 기능만 제공한다.

**앞으로**: 일정 · 주차 · 장소 · 날씨 연동은 동력원과 무관하다. 그래서 이것이 "모든 차량에서 매일 쓰는 이유"의 다음 단계다(6절).
