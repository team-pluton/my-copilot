# DEMO SCRIPT V5 — 60초 통합 시연 (2026-11-03 개정)

> 오너 결정(2026-11-03): 기능을 따로 보여 주지 않는다. **하나의 이동 목적 아래에서 차량 준비 → 여정 판단 → 방문 중 결정 → 남은 일정 유지**가 이어지는 한 장면을 보여 준다.
> 가족 여행(서울→부산)은 **편도 그대로**다 — 에너지 47% 부족 시연값과 테스트를 지킨다. 왕복 Mission 의 연결은 **픽업 후 귀가** 하나로 보여 준다. 새 기능·새 화면 없음.
> 첫 문장에 "차량 값은 시연 데이터"를 넣는다(정책 4). 내비 목적지를 앱이 설정한다고 말하지 않는다 — 공식 API 미확인.

## 영상 첫 화면 — 무엇이 다른가 (비교 범위를 밝힌다)

비교 대상은 **Pleos Connect Emulator v2.1.0 이미지의 기본 앱**(내비 Navi42 · 차량 설정 앱, `docs/research/PLEOS_PLATFORM.md` 13절, 2026-10-30)이다. 실차·다른 차종·마이현대는 확인하지 않았다 — "기존 서비스에는 없다"고 단정하지 않는다.

| 이 에뮬레이터 이미지의 기본 앱으로 할 때 | MY CO-PILOT |
|---|---|
| 운전석(시트 프리셋)과 공조를 따로 설정 | 운전자 · 동승 조합 · 목적을 함께 보고 다른 것만 한 번에 승인 |
| 내비는 목적지(학원)까지 — 기다렸다 집에 가는 일정은 사용자 몫 | 픽업 장소 도착 뒤에도 귀가 일정을 기억 |
| 대기 중 공조가 배터리에 주는 영향은 사용자가 짐작 | 확인된 대기 조건(차 안 20분)을 같은 계획에 넣어 셈 — 이 경우 **약 0~1%p**, 작다고 그대로 말한다 |
| 앱을 다시 열면 이동 맥락을 다시 고름 | 진행 중 Mission 을 이어서 복원 |

## 왜 픽업 Mission 하나인가

| 연결 고리 | 픽업 후 귀가에서 나오는 장면 | 증거 등급 |
|---|---|---|
| 운전자별 차량 환경 | 엄마 · 가족 → 운전석은 엄마 취향(열선) · 공조·음악은 가족 취향 → 다른 것만 승인 하나 → "적용 확인" | **[에뮬]** 열선 set → 콜백 → 재조회(E21 · E22-03) |
| 동승자 조건 | 돌아오는 길에 아이가 탄다 — 하차 항목 "아이 가방" · 가족 공조 | [모의] |
| 여정 판단 | 왕복 24km + 차 안 대기 20분을 한 계획으로 세어 "충전 없이 왕복할 수 있을 것으로 예상돼요 (추정)" — 대기 20분이 바꾸는 양은 **약 0~1%p**(차 안 vs 차 밖, 같은 엔진으로 계산 2026-11-03) | [에뮬] SOC 콜백 · 판단은 쉼표 DRIVE 엔진 |
| 도착 ≠ 완료 | 학원에 주차해도 "픽업 후 귀가 · 도착" — 귀가 일정 기억 중 | [에뮬] 화면(E22-07) · 도착 전환은 **[모의 주행]** |
| 방문 중 결정 | 카드 "방문을 마치셨나요? / 귀가 일정이 남아 있어요. / 다음 이동: 집으로 / 내비게이션 목적지는 직접 설정해야 합니다." → [귀가 일정 확인] → "귀가 확인 · 내비 미설정" | [에뮬] 화면(E22-08·09 — 새 문구로 재촬영) |
| 앱이 꺼져도 | 강제 종료 · 재부팅 뒤 같은 Mission 으로 이어짐 | **[에뮬]** E22-06 · E22-10 |

## 말하지 않는 것

- "내비에 집이 자동으로 설정됩니다" — **구현하지 않았다**. 공개 NaviHelper 에서 목적지 설정 API 를 확인하지 못했다(경유지 API 만 확인).
- "에뮬레이터에서 주행을 자동으로 인식했다" — 이 이미지에는 속도 신호가 없어 기어 D 만으로는 단계가 넘어가지 않는다. 학원 도착은 개발용 **모의 주행 스위치**로 재현했다.
- "실차에서 확인" — 에뮬레이터뿐이다.
- "AI 가 알아서" · "동승자 자동 감지" · "운전자 자동 인식".
