# MY CO-PILOT V5 — 제품 정의 · 고객 문제 · 차별성 (2026-11-02)

> V5 지시서(오너) 0·2·11·12절을 구현 상태에 맞춰 적은 것이다. "구현 완료"라고 쓴 것은 코드와 테스트가 있는 것, "확인"은 에뮬레이터에서 본 것이다(`SDK-EVIDENCE-V5.md`).
> 출품작 쉼표 DRIVE v3.1 과는 별개다 — 쉼표 DRIVE 는 **충전을 어떻게 결정하는지**를, MY CO-PILOT V5 는 **이동 전체를 어떻게 관리하는지**를 바꾼다.

## 1. 한 줄

**MY CO-PILOT — 목적지만 아는 차에서, 이동의 이유와 다음 행동까지 이어주는 차로.**

보조: 누가 함께 타는지, 왜 이동하는지, 도착 후 어떤 일정이 남아 있는지를 연결해 필요한 차량 준비와 이동 결정을 제안하는 개인화 코파일럿.

범용 AI 비서가 아니다. 차량에서 확인 가능한 정보(Vehicle SDK · AAOS · NaviHelper), 사용자가 고른 이동 목적, 명시적으로 저장한 선호를 결합하는 **규칙 기반** 시스템이다. 음성으로 목적을 말하면 전부 추론하는 기능은 만들지 않는다(CLAUDE.md 정책 5).

## 2. 제품의 주인공

공조도, 충전도, 체크리스트도 아니다. **하나의 이동 목적(Journey Mission)을 끝까지 관리하는 경험**이다.

| | V4(2026-10-28) | V5 |
|---|---|---|
| 핵심 문구 | 누가 탔는지 기억하고 차량 환경을 준비한다 | 왜 이동하는지 이해하고, 그 목적을 마칠 때까지 돕는다 |
| 사용자가 고르는 것 | 탑승 조합(혼자·가족·동승자) | 같은 화면에서 **이동 목적**까지 — 혼자 출퇴근 · 업무 방문 후 복귀 · 가족 이동·여행 · 픽업 후 귀가 (+ 동승 외출) |
| 공조·시트·에너지 | 전면 기능 | Mission 을 수행하는 **내부 기능**(출발 준비 카드 안) |
| 화면 최상단 | 차량·여정 상태 칩 | **Mission 목적 · 단계 · 복귀 유지 · 대기의 출처** |
| 도착 뒤 | 하차 확인 → (왕복이면) 대기 | 같음 + **"귀가 일정을 확인할까요?"** 한 번(결정 등급) · "귀가 확인 · 내비 미설정" 상태 — 경로는 운전자가 내비에서 설정 |
| 앱 재시작 | 처음부터 | **확인된 Mission 상태를 이어서**(웹 · 차량용 앱) |

## 3. 해결할 고객 문제

내비는 목적지를, 차량 설정은 운전자 선호를, EV 기능은 충전 정보를 따로 준다. 사용자는 이것을 **직접 연결**해야 한다 — 누가 탔나 · 가족이 편한 환경은 · 중간에 쉬나 · 충전이 필요한가 · 도착 후 대기·방문이 있나 · 귀가가 남았나.

핵심 문제는 "차량에 기능이 부족하다"가 아니라 **"차량 기능과 이동 일정이 분리돼 있어 사용자가 직접 연결해야 한다"**이다(`FIT-2026-10-28.md` 1절과 같다).

현대차 기본 서비스가 이미 하는 것은 **인정**한다 — 에뮬레이터 이미지의 차량 설정 앱에 시트 프리셋 1·2, 사전 공조 스케줄, 충전 목표, 캠핑 모드 등 편의 기능 7종, Gleo AI 설정이 있다(`docs/research/PLEOS_PLATFORM.md` 13절, 2026-10-30). 운전자별 프로필·원격 공조는 마이현대·블루링크가 한다. 우리는 **그 기능들을 하나의 이동 목적에 맞게 연결하는 경험**만 차별성으로 말한다.

## 4. 차별성 — 이렇게 보이면 안 된다 · 이렇게 보여야 한다

보이면 안 되는 것: 공조 온도를 기억하는 앱 · 시트를 바꾸는 앱 · 충전소를 검색하는 앱 · 체크리스트를 띄우는 앱 · 내비를 한 번 더 보여 주는 앱.

주장: **"차량 기능을 개별적으로 실행하는 것이 아니라, 하나의 이동 목적에 맞게 판단과 준비를 연결한다."**

검증 질문 셋과 지금 답:

1. 기존 차량 기능만 쓸 때 사용자가 따로 판단해야 하는 일 — 탑승 조합 선택 뒤 공조·시트를 각각 설정, 중간 목적지 도착 뒤 귀가 경로를 다시 생각, 대기 중 공조 소비를 셈, 앱이 꺼지면 처음부터.
2. MY CO-PILOT 으로 줄어드는 것 — 선택 1탭 → 비교 자동 → 승인 1탭(V4), 대기 중 "귀가 일정 확인" 1탭, 재시작 0탭(V5). 탭 수는 `UX-FLOW-V5.md`.
3. 차량 데이터·내비 이벤트 없이 같은 경험이 되는가 — 안 된다: 주차(기어 P)·공조 조회·배터리·남은 거리가 단계 전이와 판단의 입력이다. 없으면 "확인 못 함"으로 보류한다.

## 5. 사업성 방향(지시서 12절 그대로)

대상은 특정 차종·전기차 사용자가 아니다 — 반복 출퇴근·업무 방문 운전자 · 가족 장거리 운전자 · 자녀·가족 픽업을 반복하는 운전자. 초기 핵심 고객은 **반복적인 복합 이동을 수행하는 가족 운전자**. MAU·유지율 같은 수치는 근거 없이 만들지 않는다(접수양식 6번에는 "목표"라고 쓴다). 유료 구독을 억지로 넣지 않는다 — 차량 플랫폼의 고객 경험 강화·재사용성으로 정리한다.

## 6. 하지 않은 것(지시서 1절·10절)

쉼표 DRIVE 출품본 변경 0 · 기존 엔진 삭제·재작성 없음 · 새 탭 없음 · 범용 챗봇·독립 음악 플레이어·자체 내비 없음 · 음악 자동 재생·운전자 자동 인식·실내 조명 분위기·원격 준비는 **미지원**으로 표시.
