## 1. ENERGY 100점이 다른 제안을 늘 가리는 원인

- `src/lib/assistant/planner.ts:142` — 충전 제안은 관련성 1 · 중요도 1(SHORT) · 시점 1 · 새로움 1 로, 공식(`:204`) 최댓값 **100** 이 나온다.
  공조 제안은 중요도 0.6 이라 **90** 이 상한이다. 둘이 같은 점수 하나로 겨루므로(`:216` 정렬) 부족 판정이 있는 한 공조·준비물은 앞에 올 수 없다.
- 위험(부족)과 일상 준비(공조)를 **같은 축**에서 비교하는 것이 원인이다. 점수 가중치를 바꾸는 것으로는 풀리지 않는다 — 어느 쪽이든 하나가 늘 이긴다.
- 덧붙여 보이는 문제: 홈은 1개만 앞에 내고 나머지는 "추천함"에 섞어 둔다. 출발 준비처럼 **함께 할 일**이 있는 단계에서도 하나만 보인다.

## 2. 재판단 알림이 직전 값과만 비교하는 곳

- `src/components/copilot/copilot-sim.tsx:337` — `rejudge(estimate(remainPlan, v), estimate(next…))`. **바로 앞 계산**과 다음 계산을 비교한다.
- `src/lib/core/energy.ts:207` `rejudge(prev, next, threshold = 3)` 자체는 "두 계획을 비교"하는 순수 함수라 문제가 없다. 문제는 **무엇을 prev 로 넘기느냐**다.
- 결과: 대기 +30분(+1.3%p)을 세 번 하면 누적 +3.9%p 인데 알림 0회(76장면 #62·#63 에서 확인).
- 쉼표 DRIVE `/demo` 도 같은 방식(`simulator.tsx` updateVehicle)이다 — **출품작에도 같은 한계가 있다.** 이번에는 MY CO-PILOT 쪽 정책으로 먼저 고치고, 출품작 반영은 오너 결정.

## 3. 주행 화면의 음수 값

- `src/components/copilot/copilot-sim.tsx:480` 이 쉼표 DRIVE 의 `DrivingScreen` 에 `arrivalPct={energy.arrivalPct}` 를 넘긴다.
- `EnergyPlan.arrivalPct` 는 "도착 시 예상 잔량(대기 포함). **모자라면 음수일 수 있다**"(`energy.ts` 주석). 가족 시나리오는 68 − 93.4 − 1.7 ≈ **−27** → 화면에 "도착 예상 잔량 −27%".
- 즉 −27% 는 **실제 SOC 가 아니라 도착 예상 잔량의 계산값**이고, 사람이 알고 싶은 것은 "얼마나 더 필요한가(부족분)"다. 상태 화면(`screens.tsx:97`)은 이미 부족할 때 부족분을 보여 주는데, 주행 화면만 그대로다.
- **쉼표 DRIVE `/demo` 의 주행 화면(`simulator.tsx:360`)도 같은 음수를 보여 준다** — 출품작 버그. 이번 범위에서는 고치지 않고 보고한다(오너 결정).

## 4. JOURNEY 와 WAIT 의 여정 완료

- `src/lib/assistant/journey.ts:100` — `FINISH_DONE` 이면 무조건 `COMPLETED`. 여정에 **구간(leg) 개념이 없다.**
- 업무 이동(WAIT)은 에너지 계산만 왕복(`TripPlan.returnKm`)이고, 여정 단계는 고객사 도착 → 하차 → 완료로 끝난다. 귀로 에너지는 화면에서 사라진다.
- `remainPlan`(`copilot-sim.tsx:134`)은 가는 길 남은 거리만 줄이고 `returnKm` 은 그대로 둔다 — 귀로를 달리는 상태를 표현할 자리가 없다.

## 5. 프로필별 개인 설정과 이동 기록의 경계

- `copilot-sim.tsx:44` — 저장 형식은 `{ profiles, activity }`. **이동 기록(activity)은 프로필 구분 없이 하나**다. 업무 프로필에서 가족 이동 기록이 보인다.
- 제안 거절 기록(`history`)은 저장하지 않고, 프로필을 바꿔도 **그대로 이어진다** — 가족 프로필에서의 거절이 업무 프로필 제안을 막는다.
- 준비물·하차 체크 상태(`packed`·`checked`)도 프로필을 바꿔도 남는다.
- 앱을 다시 열면 항상 가족 프로필로 시작한다(어느 프로필을 복원할지 정책 없음).

## 6. 타임아웃 뒤 늦게 오는 콜백

- `copilot-sim.tsx:279~295` — 공조 변경은 `setTimeout` 하나로 결과를 정한다. **요청 ID 가 없다.**
- 모의 "응답 없음"은 콜백이 영원히 안 오는 경우만 있다. 실제로는 5초 뒤 타임아웃 → 10초 뒤 적용될 수 있는데, 지금 구조에서 "다시 시도"를 누르면 **같은 명령이 두 번** 간다.
- 타임아웃 = 실패로 확정한다(`gate.ts` settleControl → TIMEOUT). 실제로는 **결과를 모르는 상태**다.

## 7. 주행 전환 뒤 남은 승인 상태

- `copilot-sim.tsx:276` 의 `CONFIRMING`(확인 카드)은 주행이 시작돼도 그대로 남는다. 주차하면 **출발 전의 확인 카드가 다시 열린 채** 보인다.
- 실행 직전 재검사(Safety Gate)가 있어 위험한 실행은 막히지만, 오래된 승인 화면이 남는 것 자체가 혼란이다.

## 덧붙여 찾은 것

- 홈·주행 화면에 개발자 표현이 보인다: "상태 주차 · 차량 확인", 추천함의 점수 숫자. 셸 아래 디버그 줄(`ENERGY_DECISION 100`, `PARKED (CONFIRMED)`)은 조작판 영역이라 괜찮지만 **디버그라고 표시하지 않았다.**
- 혼자 이동(SOLO) 프로필에도 하차 체크리스트가 기본으로 있어, "아무 제안도 필요 없는 출퇴근"을 만들 수 없다.
- 차량 연결이 끊겼을 때를 표현할 방법이 없다 — 마지막 값이 그대로 현재 값처럼 쓰인다.
