# 쉼표 DRIVE vs MY CO-PILOT — 비교 평가표

> 작성 2026-10-26. **결론을 미리 정하지 않는다** (오너 지시). 이 문서는 평가 방법과, 두 제품에 대해 **지금 확인된 사실**만 담는다.
> 점수 칸은 비워 둔다 — 평가자가 채운다. 사실이 바뀌면(설명회 답·에뮬레이터 결과) 2절을 고치고 날짜를 적는다.

## 1. 평가 항목 — 공식 심사 기준과의 연결

공식 1차 서류 기준은 **차량특화성 · 창의성 · 기술 활용성 · 사업성** + 산출물 가산점이고, 2차 PT 는 **실제 동작하는 앱 시연이 필수**다(`docs/00-contest.md`, 배점 비공개).
아래 7개 항목은 그 기준을 쪼갠 것이다. 가중치는 정하지 않았다 — 배점이 공개되지 않았기 때문이다.

| # | 항목 | 공식 기준 | 1점 | 3점 | 5점 |
|---|---|---|---|---|---|
| 1 | 차량 특화성 | 차량특화성 | 폰 앱으로 똑같이 된다 | 차량 데이터가 있으면 더 낫다 | 차량 데이터·기능 없이는 성립하지 않는다 |
| 2 | 창의성 | 창의성 | 이미 있는 기능이다 | 있는 기능을 새로 조합했다 | 경쟁 기능에서 확인되지 않은 판단을 한다 |
| 3 | 기술 활용성 | 기술 활용성 | SDK 를 쓰지 않거나 장식으로 쓴다 | 핵심 기능 일부에 SDK 를 쓴다 | 핵심 판단의 입력·출력이 전부 SDK 다 |
| 4 | 실제 사용자 가치 | 사업성 | 없어도 불편하지 않다 | 특정 상황에서 도움이 된다 | 안 쓰면 손해가 분명한 결정을 돕는다 |
| 5 | 반복 사용 가능성 | 사업성 (MAU · Retention) | 한 번 쓰고 만다 | 특정 이동 때마다 쓴다 | 차를 탈 때마다 쓴다 |
| 6 | 구현·운영 위험 (낮을수록 높은 점수) | 2차 PT 필수 시연 | 핵심이 미확인 권한·데이터에 달렸다 | 일부가 미확인이다 | 확인된 API 만으로 핵심이 동작한다 |
| 7 | 시연 완성도 | 가산점 · 2차 PT | 화면 설명뿐 | 웹 시연이 동작한다 | 실제 앱이 기기·에뮬레이터에서 동작한다 |

## 2. 지금 확인된 사실 (2026-10-26)

두 제품 모두 차량 값은 **모의**이고, 에뮬레이터 실행은 **둘 다 아직**이다.

| # | 쉼표 DRIVE v3.1 | MY CO-PILOT (v4 실험) |
|---|---|---|
| 1 | 입력: EvBattery 잔량·효율, NaviHelper 도착 잔량 예측·남은 거리. 출력: 내비 경유지·차량 TTS. 폰 앱은 이 값을 읽지 못하고 경유지를 꽂지 못한다 | 쉼표 DRIVE 입력 전부 + 기어·주행 제한·주차 브레이크(여정 단계), HVAC 설정 온도, 도어 상태. 하차 체크리스트 자체는 차량 데이터 의존이 낮다(도어 상태만) |
| 2 | 도착 후 대기·귀가 에너지 · 동승자 조건 · 충전 정차 = 휴식 · 만약에 비교 — 경쟁 분석에서 현대 기능으로 "확인되지 않음" | 여정 단계로 "지금 제안 하나" · 근거 표시 · 실행 직전 재검사. 출발 전 공조는 마이현대 원격 공조·차량 프로필과 **겹칠 가능성 — 비교 안 함(미확인)** |
| 3 | Vehicle·NaviHelper·TTS 실물 SDK 를 **앱에 연결**, 폰 설치(차량 검증 아님), 어댑터 컴파일 | 위 + AAOS CarUxRestrictions·CarPropertyManager, HVAC·Door 읽기 — **컴파일까지**(copilot-adapters). 제어는 권한 미확인이라 만들지 않음. Pleos 차량용 앱(`android/copilot`)은 판단을 같은 core 세션으로 돌린다 — Automotive 기기에서만 AAOS 주행 신호·Pleos 배터리를 붙이고(콜백 미확인), 그 밖에서는 모의 |
| 4 | EV 장거리·마중에서 "충전하러 서야 하나" 결정. 대상은 EV 운전자, 상황이 정해져 있다 | 출발·주행·도착의 반복 상황. **다양한 동력원의 Pleos 지원 차량을 대상으로 설계**(오너 결정 2026-10-28, 차종별 지원은 Capability 검증 전 미확정) — 공통 기능은 동력원 무관, EV 에너지 판단은 차량별 특화 기능. 공조 맞추기·체크리스트 **단독 가치는 작을 수 있다** — 사용자 평가 없음 |
| 5 | 장거리·마중 때만 — 외부 평가 2 "사용 빈도가 제한적" | 탑승할 때마다 — 높을 수 있다. 제안 피로 위험은 거절 학습(10분 쉼 · 3회 연속 거절 → 추천함)으로 줄였다 |
| 6 | 에뮬레이터 실행 전 · 휴게소 실데이터 미확보 · 내비 잔량 예측 단위(%) 미확인 | 위 전부 + 제어 권한(CONTROL_*) 미확인 · 도어 위치 범위 해석 가정 · 실험 앱은 모의 차량만(어댑터 미연결)·실기기 미실행 · 범위가 넓다 |
| 7 | 웹 /demo 투어 11단계 · release APK 실기기 동작 · 48초 영상 · 기획서 PDF · 접수양식 02 작성본 | 웹 /copilot 시나리오 6개(헤드리스 확인, 콘솔 오류 0) · 근거 표시 · 실험 APK 빌드(별도 applicationId, 출품 APK 와 나란히 설치) — **실기기 실행·영상 없음** |

테스트(같은 날, 2차 개선 뒤): TS 116/116 · Kotlin 143/143(웹 시나리오를 CopilotSession 으로 재현 — PARITY.md) · `:app`·`:copilot` release 빌드 통과 · 출품 파일 변경 0. Pleos Connect Emulator 실행은 둘 다 전.

## 3. 블라인드 평가 방법

> 2026-10-27 확정 묶음(3~5명 · 공통 과제 · 추가 가치 분리 · 진행자 도구)은 **`eval/`** 폴더다 — PROTOCOL.md 가 절차, 아래는 처음 적은 7항목 평가의 원형으로 남긴다.

1. **이름을 가린다.** 두 시연을 "제품 X / 제품 Y" 로 부르고, 순서는 평가자마다 바꾼다. 화면 상단 이름(쉼표 DRIVE / MY CO-PILOT)은 시연자가 가리거나 미리 말하지 않는다.
2. **같은 상황 두 개로 본다.** ① 가족(어린이·반려견) 서울→부산, 도착 후 40분 대기 ② 업무 고객사 왕복, 90분 대기.
   제품 X·Y 모두 같은 상황을 처음부터 끝까지 보여 준다. 각 7분 이내.
3. **평가자는 항목마다 1~5점과 한 줄 근거**를 적는다. 근거 없는 점수는 버린다.
4. **모의 표시를 지운 시연은 평가하지 않는다.** 두 제품 모두 차량 값이 모의라는 것을 평가자에게 같은 말로 알린다:
   "두 시연의 차량 값은 모의입니다. 실제 차량 연결은 이 웹 시연에는 없습니다." (차량용 앱의 에뮬레이터 확인(2026-10-29)은 평가 대상이 아니므로 말하지 않는다 — 두 제품을 같은 조건으로 둔다)
5. **집계는 항목별 중앙값.** 평가자 간 차이가 2점 이상인 항목은 근거를 같이 읽고 다시 본다. 합계·가중 평균은 내지 않는다(배점 비공개).
6. **설명회 뒤 한 번 더.** 질문 10~12 의 답으로 6번(위험) 사실이 바뀌면 2절을 고치고 6·3번 항목만 다시 평가한다.

## 5. MY CO-PILOT 이 쉼표 DRIVE 보다 사용자에게 더 주는 것 — 2차 개선 뒤 (2026-10-26)

**내부 비교다. 사용자 평가가 아니다.** 같은 시나리오에서 "사용자가 앱 밖에서 직접 기억하거나 판단해야 하는 것"을 나란히 적었다.
두 제품 모두 에너지 판단은 같은 엔진(쉼표 DRIVE `estimate`)이다 — 차이는 판단 **앞뒤**에 있다.

| 상황 | 쉼표 DRIVE v3.1 — 사용자가 직접 할 것 | MY CO-PILOT — 사용자가 직접 할 것 | 줄어든 것 |
|---|---|---|---|
| 가족 장거리 출발 전 | 공조 온도·아이·반려견 준비물은 앱 밖에서 스스로 기억 · 충전 판단과 경유지는 앱 | 한 문장("두 가지는 확인됐고, 충전 계획 한 가지만 남았습니다")을 보고 남은 것만 | 출발 전 확인 목록을 기억할 일 |
| 업무 미팅이 길어짐 | 대기는 "차 안에서 기다릴 시간"으로만 센다 — 차를 두고 다녀오는 미팅인지 사용자가 해석 | 대기 유형을 한 번 알려 주면, 영향 없는 연장은 알리지 않는다 · 차 안이면 "약 145분까지" | 경보를 해석할 일 · 불필요한 알림 |
| 판단이 나빠짐 | 재판단 알림 + 만약에 비교(공조 끄고 · 대기 30분 줄이면) — **쉼표 DRIVE 에도 있다** | 같은 비교에 "차를 두고 다녀오면" · "1위 후보에서 80% 충전하면" · 대기 한계가 더해진다 | 다음 행동을 고를 근거 하나 더 |
| 왕복 귀가 | 왕복 에너지는 센다. 지금 어느 구간인지·도착이 끝인지는 없다 | 방문 중 → 귀가 구간 → 집에서 최종 하차. 휴게소 하차는 여정을 끝내지 않는다 | "아직 돌아갈 길이 남았나"를 기억할 일 |
| 도착·하차 | 없다 | 프로필별 체크리스트(사용자 확인 기록 — 센서 판정 아님) · 조회 가능한 도어 상태 | 놓고 내리는 것 확인 — **가치 미검증** |
| 출퇴근 | 장거리용이라 쓸 일이 적다(외부 평가 "사용 빈도 제한적") | 다 준비됐으면 묻지 않는다("출발 준비가 끝났습니다") | 없음 — 조용히 있는 것이 결과 |
| 첫 이용 | 프리셋 모드 → 조건 | 프로필 없이 시작 → 충전 판단 하나 · 기록 안 남김 | 첫 설정 |
| **대표 1 · 업무일 하루(충전 없음)** | 충전이 필요 없으면 쓸 일이 거의 없다 | 출발 전 준비물만 확인 · 주행 중 조용 · 고객사·집 하차 확인 2번 · 미팅 연장은 알리지 않음 · 귀가 구간을 기억 | 충전이 필요 없는 날에도 할 일이 정리된다 — **사용자 평가로는 확인 전** |

**더 주지 않는 것 · 더 생기는 위험** (결론에 넣지 않는다 — 평가자가 본다)
- 공조 맞추기는 마이현대 원격 공조·차량 프로필과 겹칠 수 있다(비교 안 함). 제어 권한(CONTROL_*)은 미확인이라 실제 차량에서 못 할 수 있다 — 그때 출발 준비의 공조는 "직접 확인"으로 바뀐다(C).
- 화면·상태가 늘었다. 쉼표 DRIVE 는 한 가지 질문(서야 하나)에 답하고, MY CO-PILOT 은 이용 과정 전체를 따라간다 — 기능이 많을수록 시연·심사에서 설명할 것이 많다.
- 대기 유형·체크리스트는 사용자가 알려 줘야 한다. 자동 감지가 아니다.
- 두 제품 모두 Pleos Connect Emulator 실행 전이다.
