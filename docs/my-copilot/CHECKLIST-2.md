# MY CO-PILOT 2차 개선 — 계획과 체크리스트 (2026-10-26)

출발점: 외부 검토 「MY CO-PILOT 최신 개발 결과 검토」(A~J 시나리오 + Android 이식 결과). 1차(`CHECKLIST.md`, P0·P1 완료)는 **판단이 맞는가**를 고쳤다. 2차는 **운전자가 덜 확인하고 덜 판단하게 되는가**를 고친다.

> 차별점 한 줄(검토 결론): 차량 기능을 많이 제어하는 것이 아니라, **지금 이용 상황과 이전 결정을 기억해 사용자가 해야 할 확인과 판단을 줄여 주는 것.**

## 지키는 것 (모든 항목 공통)

- 쉼표 DRIVE v3.1 출품 파일은 건드리지 않는다 — `src/lib/core` · `src/components/demo` · `/demo` · `/proposal` · `android/app` · `apk` · `adapters` · `docs/submission`. 매 커밋 `git diff --stat` 으로 0 확인.
- 판단 규칙은 `src/lib/assistant` ↔ `core/…/assistant` 거울. 같은 이름 · 같은 기대값 테스트.
- 새 계산을 만들지 않는다 — 에너지는 쉼표 DRIVE `estimate` 를 조건만 바꿔 다시 부른다. 근거 없는 예측값 · AI 계산 없음. 수치는 늘 범위와 "추정".
- 검증 보고는 네 칸을 섞지 않는다: **SDK 컴파일 · Android 실행(Robolectric 렌더 / 실기기) · 에뮬레이터 · 실차**.

## P0 — 제품 경험

### P0-1 운전자용 홈 (3초 안에 현재 상황)
- [x] 홈 = **지금 상황 한 줄(크게) · 주요 제안 하나(제목 + 한 문장) · 주요 버튼 하나 · 함께 준비할 것 ≤2(한 줄)**. 그 밖은 홈에 두지 않는다.
- [x] 상세 화면 "왜 이 제안인가" — 근거 4종(차량 값·내 설정·추정·규칙) · 계산 범위 · 건너뛰면 어떻게 되는지. 홈에는 "자세히" 하나.
- [x] 개발자 정보(여정 단계 코드 · 제안 등급·점수 · 신호 · 모의 조작판)는 **개발자 모드**에서만. 기본 꺼짐. 웹: 셸 아래 디버그 줄을 토글로 · Android: 조작판을 "개발용"으로 표시.
- [x] 기준: 홈 본문 글자 ≥ 공식 body(28px), 보조 글 ≥ 24px(label-s 20px 는 홈에서 뺌), 주요 버튼 96px · 보조 80px(car-px). 홈 블록 = 상태 · 상황 · 제안 · 버튼 · 함께 할 일(+이동 메뉴). *픽셀 측정표는 만들지 않았다 — 클래스 기준 확인.*
- 완료 조건: A·B·G·H 홈 캡처에서 내부 코드·점수 0개 · 버튼 1(+건너뛰기 보조) · 측정표 통과.

### P0-2 출발 준비 = 하나의 준비 과정
- [x] 순수 함수 `prepareStatus` — 항목마다 `DONE | NEEDS_CHECK | UNSUPPORTED | SKIPPED` 와 한 줄.
  공조: 같음·적용 확인·그대로 두기로 함 → DONE / 다름 → NEEDS_CHECK / 읽기 불가·차종 미지원·권한 없음 → UNSUPPORTED("차량 패널에서 직접") / 목표 온도 없음 → SKIPPED.
  준비물: 다 챙김 → DONE / 남음 → NEEDS_CHECK / 목록 없음 → SKIPPED.
  에너지: 충분 또는 경유지 정함 → DONE / 주의·부족 → NEEDS_CHECK / 연결 끊김 → UNSUPPORTED("값을 기다리는 중").
- [x] 요약 문장: "출발 준비에서 두 가지는 확인됐고, 충전 계획 한 가지만 남았습니다." · 다 되면 "출발 준비가 끝났습니다 · 바로 출발하셔도 됩니다".
- [x] **UNSUPPORTED 는 남은 일로 세지 않는다**(사용자가 할 수 있는 일이 아니다) — 따로 "확인 못 함 1".
- [x] 다 되면 "출발 준비 완료" 버튼을 요구하지 않고, 출발 준비 제안도 다시 띄우지 않는다.
- 완료 조건: TS·Kotlin 같은 표 테스트(12갈래) · A(남은 1) · G(다 됨, 묻지 않음) · C(권한 없음 → 지원 안 됨) 장면.

### P0-3 대기 유형 · 차량 상태와 여정 상태 분리
- [x] `WaitMode = IN_CAR(차 안에서 공조 켜고) | AWAY(차를 두고 밖에서)`. 프리셋 기본값: 가족 IN_CAR(마중·대기), 업무 AWAY(미팅). 대기 카드에서 바꿀 수 있다(정차 중).
- [x] 에너지: AWAY 면 대기 소비 0 으로 `estimate` 를 다시 부른다 · 가정 줄을 "차를 두고 밖에서 · 대기 소비 0 (가정)"으로. 새 계산 없음.
- [x] 순수 함수 `statusOf` — **차량 상태**(주행·정지·주차·모름, 신호에서) 와 **여정 상태**(출발 전·출발 준비·이동 중·곧 도착·중간 정차·도착·차 안 대기·방문 중·잠시 내림·귀가 중·완료, 여정+대기 유형에서)를 따로 돌려준다. 화면은 둘을 섞지 않는다.
- [x] H: 고객사 "방문 중(차를 두고) · 귀가 38km 남음" · 대기 유형을 바꾸면 귀가 판단이 바뀌는 장면.
- 완료 조건: 같은 입력 TS·Kotlin 테스트 · H 장면 2개 추가.

### P0-4 에너지 판단 뒤 행동 선택지
- [x] 순수 함수 `energyOptions` — 판정이 주의·부족일 때만. 각 선택지 = 라벨 · 판정 · 도착 잔량(범위) · 앱이 해 줄 수 있는 일(있으면).
  ① 지금 계획 그대로 ② 차를 두고 밖에서 기다리면(IN_CAR·대기>0 일 때) ③ 대기를 30분 줄이면(대기≥30 일 때 · 앱이 일정을 바꾸지는 않는다 → 정보만) ④ 1위 후보에서 80% 충전하면(경유지 슬롯이 남았을 때 · "후보 보기").
- [x] "대기 약 N분까지는 충전 없이" — 대기 시간을 바꿔 `estimate` 를 다시 불러 판정이 충분으로 남는 가장 긴 대기(5분 단위, 중앙값 기준이라고 적음). AWAY 면 "차 밖 대기는 시간과 무관".
- [x] 자동으로 아무것도 바꾸지 않는다(정책 1) — 대기 유형 변경 · 후보 보기만 버튼.
- 완료 조건: TS·Kotlin 테스트 · E(충분→주의 뒤 선택지) · A(부족 → 경유지 충전이 충분으로) 장면.

## P1 — 신뢰와 일관성

### P1-1 첫 이용 간소화
- [x] 첫 화면에서 "프로필 없이 시작" — 개인 선호 없음(목표 온도·준비물·하차 목록 없음), 에너지 판단만. 이름은 "기본"(혼자 이동이라고 추정하지 않는다).
- [x] 기본 모드는 개인 기록을 남기지 않는다. 이동을 마치면 "프로필을 만들면 다음에 공조·준비물을 함께 확인합니다" 한 줄(저장은 사용자가).

### P1-2 데이터 신선도 · 출처
- [x] 순수 함수 `freshness` — 종류별 유효 기간(기어·주행 제한·속도: 연결 끊김 즉시 모름 · 배터리 10분 · 공조·도어 10분 · 프로필 선호: 기한 없음). `FRESH | STALE | UNKNOWN`.
- [x] 오래된 배터리 값으로 판단하지 않는다(모름과 같게) · 오래된 공조 값으로 "같습니다"라고 하지 않는다.
- [x] 상세 화면 근거에 "배터리 68% · 11:08 조회 · 모의".

### P1-3 Android ↔ 웹 상태 일치

- [x] 기록의 상태 이름 한국어(`APPROACHING → PARKED` 금지).
- [x] 비교표: 같은 시나리오 체크포인트마다 웹 캡처 글 vs Android(Kotlin 세션) 값 — 여정 상태 · 주요 제안 · 에너지 문장 · 준비 요약.
