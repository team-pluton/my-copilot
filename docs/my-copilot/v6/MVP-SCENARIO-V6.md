# MVP 시나리오 — 가족 서울 → 부산

조건: 400km · 어린이·반려동물 · 도착 후 40분 대기 · 경부선 부산 방향 휴게소. 기존 시연값(SOC 68%, 약 47%p 부족)은 그대로 둔다.

## 흐름

1. 가족 선택 → 출발 준비
2. 차량 SOC·용량 읽기 → 충전이 필요한가 (아니면 여기서 끝, API 호출도 없음)
3. 충전소 상태 조회 → 필수 조건으로 거르기 → 결정 하나
4. 카드: 추천 · 이유 · 도착 잔량 범위 · 충전 시간 추정 · 상태 조회/변화 시각 · 우회 "확인되지 않음" · 근거 줄 · 대안
5. [경유지로 추가] 승인 → 내비 반영 → 목록 재조회로 확인
6. 상태가 바뀌어 추천이 달라지면 이유와 함께 다시 묻기
7. 주행 중에는 한 줄

## 실제로 나온 결과 (에뮬레이터 2026-11-04)

배터리 **차량 정보** 100% · 원시 77400 → 77.4kWh · 충전기·시설·위치 **시연 데이터** · 내비 **실제**.

> 황간휴게소에서 충전하며 쉬어 가세요
> 도착 후 대기까지 세면 약 15%p(3~26%p) 부족 추정
> 도착 잔량 43~55% 추정 · 80%까지 충전 후 여유 17%p 추정 · 충전 약 14분 추정
> 우회 영향: 확인되지 않음

승인 → 내비 경로에 황간휴게소 경유 · 목적지 유지 → 앱 "경유지에 있어요: 황간휴게소".

실제 프록시 모드(키 없음): "지금은 믿고 권할 충전소가 없어요 · 충전소 상태를 받지 못했어요". 값을 지어내지 않았다.

⚠️ 지금 시연이 보여 주는 것은 **차량 + 내비 실제, 충전소는 시연**이다. 세 서비스가 실제로 한 답을 만드는 장면은 키를 받아야 가능하다.
