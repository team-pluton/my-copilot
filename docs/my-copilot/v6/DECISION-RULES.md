# 판단 규칙

순서가 곧 규칙이다. 앞 단계 실패는 뒤 단계 점수로 상쇄되지 않는다.

## 1. 판단할 자격

| 조건 | 답 |
|---|---|
| EV 가 아님 · 동력원 미확인 | `NOT_APPLICABLE` |
| 차량 값 없음 · 범위 밖 · 오래됨 | `CANNOT_JUDGE` |
| 기존 엔진이 충전 불필요 판단 | `NO_CHARGE_NEEDED` — 충전소 API 를 부르지 않는다 |

## 2. 후보별 제외 (`excluded`)

- 이미 지나온 곳
- 이번 이동에서 사용자가 거절한 곳
- 닿지 못함: `reachableState` UNREACHABLE, 또는 비관 추정(+12%) 도착 잔량이 안전 여유 8% 미만
- 필수 시설이 **없다고 확인됨**
- 규격이 모두 불일치
- 충전기가 모두 점검·운영 중지

## 3. 확인 필요 (`needsCheck`) — 동등하게 다루지 않는다

필수 시설 미확인 · 규격 모름 · 안내문에 제한 낱말 · 받은 지 오래됨 · 상태 알 수 없음 · 사용 가능 표시가 72시간 넘게 고정 · API 실패.

## 4. 비교 — 점수 합산이 아니라 사전식

1. 곧 닿는데(40km 이내) 전부 충전 중이면 뒤로
2. 한 번 충전으로 끝남 > 여유 적음 > 한 번 더
3. 대기 표시 있음
4. 정보가 최신
5. 확인된 가족 시설 수
6. 최대 출력
7. 대기 대수
8. 먼저 나오는 곳

**왜 충전 중이 앞에 오지 않나:** 3시간 뒤 도착할 곳의 지금 상태는 그때의 빈자리를 말해 주지 않는다. 그래서 먼 곳은 '충전 중'만으로 순위를 내리지 않는다. 점검·운영 중지는 거리와 무관하게 제외한다.

## 5. 답

| 결과 | 내용 |
|---|---|
| `RECOMMEND` | 추천 1 + 대안 최대 2 + 확인 필요 |
| `NO_RELIABLE` | "믿고 권할 충전소가 없어요". 가장 나쁜 곳을 억지로 권하지 않는다 |

한 번에 끝나는 후보가 있으면 한 번 더 서야 하는 후보는 뺀다.

## 6. 재판단

**추천이 바뀔 때만** 다시 묻는다. 이유는 새 판단이 적은 사실만 옮긴다. 원인을 추측하지 않는다.
데이터 출처를 바꾼 것은 판단 변화가 아니므로 비교하지 않는다.

| 상황 | 동작 | 근거 |
|---|---|---|
| 먼 곳이 사용 중으로 | 순위 유지 | 계약 |
| 곧 닿는 곳이 사용 중으로 | 다음 후보로 | 계약 |
| 점검으로 | 제외, 다음 후보, 이유 표시 | T14 |
| API 끊김 | `NO_RELIABLE`, 에너지 판단 유지 | T10 |
| SOC 감소 | 닿지 못하는 곳 제외, 없으면 추천 안 함 | 계약 |
| 거절 | 다음 후보 | 계약 |
| 경유지 콜백 없음 | '모름'으로 재조회 | T12b |
| 목적지·일행 변경 | 다시 판단 | 복구 테스트 |

## 7. 화면

주행 중이거나 움직임을 모르면 한 줄뿐이고 고를 수 없다. '사용 가능' · '확정' · '보장' 이라고 쓰지 않는다. 우회 시간을 모르면 "확인되지 않음"이고 숫자가 없다. 직선거리로 대신하지 않는다.

## 기준값은 가설이다

40km · 72시간 · 10/30분 · 5분은 근거 측정 전 값이다. DATA-FRESHNESS-POLICY 참고.
