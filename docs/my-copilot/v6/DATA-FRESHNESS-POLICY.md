# 데이터 신선도 정책

세 시각을 합치지 않는다.

| 시각 | 뜻 | 쓰임 |
|---|---|---|
| `retrievedAt` | 우리가 받은 때 | 지금 값인가 |
| `statusUpdatedAt` | 충전기 상태가 **바뀐** 때 | 오래 고정돼 있는가 |
| 도착 예정 | 경로상 위치에서 추정 | 지금 상태가 그때까지 의미 있는가 |

`statusUpdatedAt` 이 오래됐다고 곧 못 믿을 값은 아니다. 밤새 쉰 정상 충전기도 오래돼 보인다. 그래서 받은 시각이 최근이면 신뢰를 바로 낮추지 않고, **사용 가능 표시가 오래 고정**된 경우만 의심한다.

## 기준값 — 전부 가설

| 항목 | 값 | 다음 |
|---|---|---|
| FRESH | 받은 지 10분 이내 | 수집으로 조정 |
| AGING | 30분 이내 | 수집으로 조정 |
| STALE | 30분 초과 → 확인 필요 | 수집으로 조정 |
| 고정 의심 | 사용 가능 표시 72시간 초과 | 수집으로 조정 |
| 상태가 의미 있는 거리 | 40km(약 30분) | 도착 시 대조로 조정 |
| 차량 값 | 5분 초과면 판단 안 함 | 콜백 주기 확인 후 |

## 근거 등급

`VEHICLE` · `LIVE_API` · `CACHED` · `CURATED` · `MOCK` · `UNKNOWN`. 한 충전소에 섞이면 가장 약한 등급으로 표시한다. 카드 근거 줄에 항상 나온다: "배터리 차량 정보 · 충전기 시연 데이터 · 위치 시연 데이터".

## 실패

키 없음 · 거절 · 시간 초과 · 예산 소진은 값으로 메우지 않는다. 충전소 판단만 '확인 불가'가 되고 차량 값과 Mission 은 그대로다. 프록시 저장값은 받은 시각을 숨기지 않아 앱이 신뢰를 낮춘다.

## 표현

쓰는 말: "조회 시각 기준 N대 대기 표시" · "추정" · "확인되지 않음".
쓰지 않는 말: "실시간" · "사용 가능" · "확정" · "도착 보장".
