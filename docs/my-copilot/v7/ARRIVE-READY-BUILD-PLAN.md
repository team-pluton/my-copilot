# ARRIVE READY 구현 계획 — "여러 앱을 오가지 않는다"를 실제로 (2026-11-11)

> 입력: 오너 전달 평가 "3차 UI 는 기반을 다듬었을 뿐, 멀티앱 통합은 아직 EV 충전 하나뿐이다".
> 근거: 관문 A·B·C 통과(`ARRIVE-READY-FEASIBILITY.md`) · E27·E28 에뮬레이터 실측. **구현 시작 시점은 오너 결정**(CLAUDE.md: 11/15 까지 대규모 신규 구현 금지).

## 지금 실제로 통합된 것 — 정직한 표

| 묶음 | 외부 데이터 | 판단에 쓰나 | 앱 전환이 줄어드나 | 승인 → 실행 → 확인 | 조건이 바뀌면 다시 |
|---|---|---|---|---|---|
| 배터리 + 공공 충전소 API + 내비(EV) | ✅ [실 API] 77기 | ✅ 에너지 예산 · 순위 | ✅ 충전 앱 · 지도 대신 | ✅ addWaypoint → 재조회 [에뮬 E27·E28] | ✅ SOC 변화 · 상태 갱신 [에뮬 E27] |
| 픽업 Mission + 차량 설정 + 내비 귀가 | ✗ (앱 안 정보) | ✅ | 일부(내비 검색 대신 '집으로') | ✅ requestRoute → 재조회 [에뮬 E28] | 대기 계획만 |
| **일정 + 주차 + 내비(ARRIVE READY)** | 주차 ✅ [실 API] · 일정 ✗(제공자 없음 → 사용자 입력) | **미구현** | — | 관문 C 통과(코드 없음) | — |

→ 비EV 외부 서비스 통합 사례가 **0개**다. ARRIVE READY 가 첫 사례가 되어야 한다.

## v0 범위 — 다섯 기준에 맞춘 것만

| 기준(오너) | v0 에서 하는 것 | 데이터 · 근거 |
|---|---|---|
| ① 외부 데이터를 실제로 확보 | 서울 시영 주차장 **실시간 105곳**(대수 · 갱신 시각 · 운영시간 · 요금 · 좌표) | 서울 열린데이터광장 [실 API] · 프록시에 경로 추가(키는 프록시에만) |
| ② 차량·내비 정보와 함께 판단 | 후보마다 `requestTrip(주차장 좌표)` 로 **소요 시간** · 약속 시각 − 지금 − 소요 − **사용자 여유(주차 후 걸어가는 시간은 사용자가 정함, 계산하지 않음)** → 여유 있음 / 빠듯함 / 판단 불가(범위) | NaviHelper [에뮬 E27, 목적지 없이도 0.2~0.4초] |
| ③ 다른 앱을 열 일이 줄어듦 | 약속 하나 입력 → **주차장 하나 + 이유 한 줄**("빈자리 약 N면 · 16:35 기준 · 도착 예정 14:41 · 여유 약 9~15분 · 추정") | 지도 · 주차 앱 · 내비 검색 대신 |
| ④ 승인하면 실제 반영 | '이 주차장으로 안내' → `requestRoute(좌표)` → `onRouteStarted` → 목적지 재조회 확인. 기존 경로는 먼저 묻는다 | [에뮬 E27 Gate C] · V5 RouteHandoff 재사용 |
| ⑤ 조건이 바뀌면 다시 | 주차 대수 갱신(약 3분) · 소요 시간 재조회 → 판단이 바뀌면 "판단이 바뀌었어요 · 대신 ○○" — **결과가 달라질 때만** | V6 JOURNEY RECOVERY 골격 재사용 |

**만들지 않는 것**: 주차장 검색 화면 · 지도 · 일정 앱 · 걸어가는 시간·빈자리 예측(근거 없음) · 서울 시영 밖 주차장(범위 밖이라고 쓴다).
**일정**: 차량 이미지에 캘린더 제공자 없음(E27 Q8) → v0 는 **사용자가 약속 시각·장소를 입력**(또는 시연 프리셋). "일정 앱 연동"이라고 말하지 않는다.

## 신규 기능 승인 문서 A~J (`../PRODUCT-PRINCIPLES.md` 7절 — 첫 적용)

| | 답 |
|---|---|
| A 원래 하던 일 | 약속 시간·장소 확인 → 근처 주차장 검색 → 빈자리·운영시간·요금 비교 → 주차장까지 시간 확인 → 제시간에 되는지 머릿속 계산 → 내비에 주차장 입력 |
| B 오가는 앱 | 3~4개 — 일정(또는 메시지) · 지도/주차 앱 · 내비(시간 확인 + 목적지 입력). 비교는 사람이 머리로 |
| C 가져오는 데이터 | 약속 시각·장소: **사용자 입력**(차량에 일정 제공자 없음, E27 Q8) · 주차: **서울 열린데이터광장 시영 실시간 105곳**(대수·갱신 시각·운영시간·요금·좌표) [실 API] · 소요 시간: **NaviHelper `requestTrip`** [에뮬] · 목적지 실행: `requestRoute` [에뮬] |
| D 결합 판단 | 후보마다 (약속 − 지금 − 소요 시간 − 사용자 여유)를 **범위**로 → 여유 있음/빠듯함/판단 불가 · 빈자리 신선도(Gate D) · 운영시간 안인가 → 하나 추천 + 순위를 가른 기준 하나 |
| E 달라지는 행동 | 어느 주차장을 목적지로 보낼지 · 지금 출발해야 하는지 · 빠듯하면 "약속 조정이 필요할 수 있어요"(지각 시각을 만들어 내지 않음) |
| F 사용자 조작 | 약속 입력(시각·장소, 프리셋 1탭) → 추천 확인 → **승인 1탭**. 기존 경로가 있으면 교체 확인 1탭 |
| G 실행·확인 | `requestRoute(주차장 좌표)` → `onRouteStarted` → `getDestinationInfo` 같은 좌표면 "내비가 확인함" [관문 C 통과] |
| H 실패·정보 부족 | 주차 데이터 STALE → 대수를 판단에 안 쓰고 "주차 가능성 확인 안 됨" · 좌표 없음 → 제외 · ETA 없음 → "판단 불가"(추천 안 함) · 내비 응답 없음 → "설정됐는지 모릅니다" + 재조회 · 서울 시영 밖 → 범위 밖이라고 말함 |
| I 비EV | **동력원 무관** — 배터리를 쓰지 않는다(EV 면 ENERGY & STOP 이 같은 목표에 붙을 수 있음) |
| J 반복 이용 | 업무 방문 · 병원 · 학원 · 약속 — 시간이 정해진 방문은 일상적으로 반복된다 |

## 구조 — 새 탭이 아니라 '지금 이동'의 목표 카드

- Journey Goal(`JOURNEY-GOAL-SPEC.md`)이 V5 Mission 을 감싼다 — `goalType = ARRIVE_BY(시각, 장소)`.
- 판단은 순수 함수(TS ↔ Kotlin 거울): `arriveReady(goal, now, parkingFacts[], tripEtas[]) → Decision{ top, alternatives, needsCheck, budgetLine, decisiveReason }` — V6 IntegratedDecision 과 같은 모양(카드·문구 재사용).
- 신선도는 V6 규칙 + 주차 Gate D 표(STALE 이면 대수를 판단에 안 씀, 좌표 없으면 제외).
