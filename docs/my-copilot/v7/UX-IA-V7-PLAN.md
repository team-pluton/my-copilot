## 1. 정보 구조 — 기능 탭 7개 → 세 자리

지금: `홈 · 자세히 · 출발 준비 · 에너지 · 하차 · 기록 · 프로필` — 사용자가 앱의 기능을 알아야 원하는 정보를 찾는다.

| V7 자리 | 무엇 | 지금 탭에서 오는 것 |
|---|---|---|
| **지금 이동** | 현재 목표 한 줄 → **지금 필요한 행동 하나** → 여정 정보(펼침) | 홈 · 출발 준비 · 에너지 · 하차 · 자세히(근거는 카드 안 펼침으로) |
| **이동 기록** | 지난 이동 · 확인 기록(체크리스트 '확인 안 함' 포함) · 판단이 바뀐 이유 | 기록 |
| **내 설정** | 운전자·탑승 조합 취향 · 체크리스트 항목 · 안내 방식 | 프로필 |

**지금 이동** 화면의 카드는 목표 상태에 따라 나타난다(탭이 아니라):

| 카드 | 언제 | 주 행동 |
|---|---|---|
| 출발 준비 | 출발 전 · 취향과 다른 실내 설정이 있을 때 | 한 번에 적용 |
| 충전 결정(EV) | 장거리 · 에너지 예산이 모자랄 때 | 경유지로 추가 |
| 도착 확인 | 목적지 0.5km 안 + 주차 | 기다리기 시작(도착 확인) |
| 귀가·다음 목적지 | 대기 중 · 다음 구간이 남았을 때 | 집으로 출발 준비 → 안내 시작 |
| 하차 점검 | 사용자가 시작할 때만 | 확인 기록하고 마치기 |
| **ARRIVE READY** | 약속 시간이 있는 목표일 때 — **새 탭이 아니라 같은 화면의 목표 유형** | "이 주차장에 세우면 제시간에 방문을 마칠 수 있나" 판단 하나 |

규칙
- 화면에 **주 행동은 하나**. 다른 카드는 한 줄 요약으로 접는다 — 주목도만 낮추고 작업을 막지 않는다(공조 카드 접기와 같은 원칙).
- 근거·대안·진단은 카드 안 펼침. 별도 탭으로 꺼내지 않는다.
- 주행 중에는 지금처럼 한 줄 + 음성(DO).
- 할 일 없음이 정상 상태 — "지금은 드릴 제안이 없습니다".

옮기는 순서(11/15 뒤): ① 출발 준비·에너지 탭 내용을 홈 카드 펼침으로 ② 하차 탭을 '하차 점검' 카드로 ③ 자세히 → 카드 안 '왜?' ④ 탭 줄을 세 자리로 ⑤ ARRIVE READY 카드(관문 A~E 통과 후).

## 2. 데이터 공급자 분리 — Debug · Demo · Release

지금(2026-11-11 확인): Automotive release 에서 화면 요소는 막았다 — `CopilotViewModel.devTools = !automotive || debuggable` 이 **개발용 조작판**과 **"80% 충전 완료 (시연)" 버튼** 둘 다를 가린다(이번에 버튼 하나를 더 찾아 막음).
조작판은 헤더 버튼 하나로만 열리고, 매니페스트에 외부 진입점(receiver·provider·인텐트 값 읽기)은 없다.
**남은 한계**: 모의 값을 넣는 코드(`Intent.Charge · JumpTo · SetCar · AdvanceClock`, 시연 충전소 데이터)는 release APK 안에 그대로 있다 — 화면에서 부르지 못할 뿐이다.

| 빌드 | 차량·내비 값 | 충전소 | 모의 주입 | 조작판 |
|---|---|---|---|---|
| Debug | 실제(있으면) → 없으면 모의 | 프록시 / 시연 선택 | 허용 | 표시 |
| Demo(심사·영상) | 실제 → 없으면 모의, 화면에 '시연 데이터' 배지 | 시연 고정 가능 | 시연 상태에서만 | 제한 표시 |
| Release | 실제만 · 없으면 '모름' | 실제 API 만 | **코드 없음** | **없음** |

구현안: Gradle `productFlavors { debugTools; release }` — 모의 공급자(`DemoData`, 시연 충전소, 조작판 Composable)를 `src/debugTools/` 로 옮기고 release 소스셋에는 인터페이스만. 세션의 모의 Intent 는 공급자 인터페이스 뒤로.
검증: release APK 를 `apkanalyzer dex packages` 로 열어 모의 클래스가 없음을 확인 · 에뮬레이터에서 조작판·시연 버튼 미표시.
