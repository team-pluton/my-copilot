# MY CO-PILOT V7 — Journey OS · 제품 비전 (2026-11-10)

> **2026-11-11 위에 놓인 것 — `../PRODUCT-PRINCIPLES.md`(최상위 제품 원칙).** 이 비전은 그 원칙 아래에서 읽는다.
> 바뀐 점: 주력 경험이 **넷**이다 — ARRIVE READY(1순위) · JOURNEY RECOVERY · **FAMILY JOURNEY**(픽업·대기·귀가 Mission, 아래 세 모듈 표에는 없던 이름) · ENERGY & STOP. 공조·시트 개인화는 보조 기능.

> 오너 결정(2026-11-10, 「MY CO-PILOT 전면 재설계안」): 기능 중심·충전 중심 설명을 폐기하고 **이동 목표 중심 멀티서비스 의사결정 서비스**로 전환한다.
> 이 문서가 V7 의 정답이다. 2026-11-09 정의(`../PLATFORM-2026-11-09.md` — 통합 어시스턴트 · 세 축)는 **버리지 않고 이 문서 아래로 들어온다**: 세 축은 Journey Goal 을 이루는 방식이다.
> 증거 등급: **[에뮬]** Pleos Connect Emulator 실측 · **[실 API]** 외부 API 실호출 · **[시연]** 시연 데이터 · **[미구현]** 설계·계획 · **[검색]** 오너·검색 조사(원문 미확인).

## 한 문장

**목적지를 알려주는 차에서, 목적을 달성하도록 돕는 차로.**

MY CO-PILOT 은 차량 상태 · 내비게이션 · 외부 서비스의 정보를 연결하여 운전자의 **실제 이동 목표**를 달성하는 데 필요한 다음 행동을 판단하고, 승인된 행동의 **실행 결과까지 확인**하는 차량용 코파일럿이다.

- **Journey OS** 는 서비스 콘셉트 이름이다. Android Automotive 나 Pleos 운영체제를 대체하지 않는다 — 운전자의 이동 목표를 관리하는 **애플리케이션 계층**이다.

## 무엇이 바뀌나 — "이동 상태를 기억한다" → "이동의 성공 조건을 관리한다"

고객사에 가는 목적은 건물 앞 도착이 아니다. **약속 시간에 맞춰, 실제로 주차하고, 방문 장소까지 들어갈 수 있어야** 이동이 성공한 것이다.
내비게이션은 경로에 강하다. MY CO-PILOT 은 그 경로 **전후의 실제 목적**까지 잇는다.

| 이전(V6까지) 사용자에게 보인 것 | V7 |
|---|---|
| 모드 고르기(혼자·가족·동승자) → 취향 비교 → 제안 카드 → 차량 상태 | **오늘의 이동 목표** → 지금 판단할 문제 하나 → 추천 하나 → 대안 → 승인 → 반영 확인 |
| 공조·시트 개인화가 전면 | 개인화는 **배경** — 판단에 필요할 때만 나온다 |
| EV 충전 판단이 대표 사례 | EV 는 **ENERGY & STOP 모듈**(EV 특화). 대표 경험은 동력원 무관 **ARRIVE READY** |
| 13개 시나리오 투어 | 개발 QA 로 이동. 사용자에게는 목표 하나 |

| 순위 | 무엇 |

| 첫 신규 경험 | **ARRIVE READY** |
| 기존 실증 | 픽업 Mission(V5) · EV 통합 판단(V6 — 전체 제품이 아니라 실증 모듈) |
| 후순위 후보 | 픽업 + 날씨·교통 (2026-11-09 F2 의 "A 우선"을 **대체**) |

가족 모드 · 체크리스트 · 공조 프리셋을 제품의 대표 혁신으로 내세우지 않는다.
11/15 전에는 검증된 앱의 안정성 · 양식 02 · APK · 시연 영상 · 익명성이 먼저다. V7 신규 개발은 `v7-journey-os` 이후 브랜치에서, 제출본·테스트·증거를 건드리지 않고.

### ARRIVE READY 의 기준 — 주차장 추천이 아니다

답할 질문: **"이 주차장에 차를 세우면, 약속한 시간에 실제로 방문을 마칠 수 있는가?"**

| 일반적인 통합 앱 | ARRIVE READY 목표 |
|---|---|
| 주변 주차장 검색 | 약속 시간에 맞는 주차 후보 판단 |
| 가장 가까운 주차장 추천 | 이동 · 주차 · 방문 여유 종합 |
| 주차장 정보 표시 | 주차 정보의 **신선도**까지 평가 |
| 목적지 내비 실행 | 승인된 방문 계획을 내비에 연결하고 재조회 |
| 도착 후 종료 | 방문 목적 달성과 다음 구간(귀가) 연결 — V5 Mission |

실시간 주차 · 소요 시간 근거가 없으면 확정하지 않는다. 주차 후 도보 시간은 공급원이 없어 **사용자 설정 여유**만 쓴다(`ARRIVE-READY-FEASIBILITY.md`).

공통 기반 — **Journey Goal Engine**(`DECISION-ENGINE-V7.md`): 목표 확인 → 제약 추출 → 데이터 조회 → 위반 후보 제거 → 추천 하나 + 대안 → 승인 → 공식 SDK 실행 → 재조회 확인 → 목표 갱신.
기존 자산(V5 Mission · 개인화 · V6 Decision Engine · Safety Gate · FactMeta · 승인→실행→재조회)이 그대로 이 엔진의 부품이다.

## 기존 기능과의 관계 — 다시 만들지 않는다

| 이미 있는 것 | 하는 일 | MY CO-PILOT 이 하는 일 |
|---|---|---|
| 기본 내비 | 경로 · 경유지 · **EV 충전 계획**(SDK 에 `ChargingPlan` 확인) · 충전소 추천 [검색] | 경로 정보를 **목표 판단의 입력**으로 쓴다. 자체 지도·턴바이턴은 안 만든다 |
| Gleo AI | 명령을 이해하고 실행 · 날씨·장소 검색·복합 명령 [검색] | 명령을 기다리지 않고 **목표 달성 조건**을 계속 관리한다. 범용 챗봇은 안 만든다 |
| Pleos ID / 차량 설정 | 운전자 개인화 [검색] · 시트 프리셋 · 사전 공조 [에뮬] | 개인화는 배경 입력. 가치로 내세우지 않는다 |

차별성은 기능 이름이 아니라 **목표 달성 조건을 지속적으로 관리하고, 외부 정보의 불확실성까지 고려해 결과를 확인하는 경험**으로 입증한다. Gleo AI 와 전혀 겹치지 않는다고 주장하지 않는다(`COMPETITOR-DIFFERENTIATION.md`).

## 지키는 것 (V6 까지의 정책 그대로)

- 자동으로 목적지·경로를 바꾸지 않는다 — 승인 뒤에만, 재조회로 확인.
- 모르는 값은 숫자로 쓰지 않는다 — **ETA·도보 시간·실시간 빈자리·지각 시각을 만들어 내지 않는다.** 근거가 없으면 "판단 불가".
- 데이터가 충돌하거나 오래되면 한쪽을 임의로 사실로 채택하지 않는다.
- 주행 중에는 한 줄 상태와 음성만(DO · Safety Gate).
- 실제 · 시연 · 미구현을 섞어 말하지 않는다.
- 정책 5 해석(2026-11-09) 유지 — 공식 장소·주차·날씨·교통 데이터를 **판단에 활용**은 허용, 지도·턴바이턴·범용 장소 검색·범용 챗봇은 금지. ARRIVE READY 는 **주차장 검색 화면이 아니다** — 후보는 판단의 재료로만 보인다.
