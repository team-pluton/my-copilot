# UX 흐름 V7 — 기능 중심에서 목표 중심으로 (설계 · 2026-11-10 · 앱 미반영)

> 앱(`android/copilot`)은 1차 제출까지 V6 화면 그대로다(`stable-copilot-v6-2026-11-10`). 이 문서는 PT 앱의 목표 화면이다.
> 원칙 그대로: 앱 창 안만 그린다(상단바·하단 탭 없음) · 세로 기본 840×1184dp · 주행 중 한 줄 + 음성 · 정차 중에만 비교 · 승인 하나.

## 기본 화면 — 다섯 칸

```
┌ 앱 창 (세로) ─────────────────────────────┐
│ A  오늘의 이동 목표                         │
│    오후 3시 고객사 미팅 · 방문 준비까지        │
│ B  지금 판단할 문제 (하나)                   │
│    주차와 이동 시간을 함께 확인해야 해요        │
│ C  추천 행동 하나                           │
│    [주차장 P1 을 목적지로]  이유 2줄 · 출처·시각 │
│ D  대안 보기 (정차 중에만 펼침, 최대 2)        │
│ E  [승인]  →  "내비 목적지 반영 확인 14:12"    │
│ ─ 세부(접힘): 차량 상태 · 개인 설정 · 데이터 출처 │
└──────────────────────────────────────────┘
```

- **A** 는 목표를 사용자가 고른다(자주 쓰는 목표 + 직접 입력: 시각 · 목적지). 일정 앱 자동 연동은 없다고 쓴다.
- **B** 는 하나만. 문제가 없으면 B·C 를 비우고 "지금 계획대로 가면 돼요" 한 줄(조용히 유지).
- **C** 의 근거에는 값마다 등급과 시각("서울시 주차정보 · 14:05 기준 · 빈자리 보장 아님").
- **D** 대안은 주행 중 숨김(DO).
- **E** 승인 뒤 "요청함" → 콜백·재조회 → "반영 확인". 확인 전에는 '완료'라고 쓰지 않는다.
- 공조·시트·배터리는 **판단에 필요할 때만** C 의 근거로 나온다. 모드(혼자·가족·동승자) 선택은 첫 화면에서 내린다 — 동승자 정보는 목표 입력의 선택 항목으로.

## 목표별 흐름

| 목표 | A | B 예 | C | E 확인 |
|---|---|---|---|---|
| ARRIVE READY · 업무 방문 [미구현] | 15:00 미팅 · 목적지 | "주차 여유를 확인해야 해요" | 주차장 P1 을 목적지(또는 경유지)로 | 목적지/경유지 재조회 |
| 픽업 후 귀가 [에뮬] | 학원 → 집 | (도착 뒤) "방문을 마치셨나요?" | 집으로 안내 시작 | 목적지 재조회 |
| ENERGY & STOP · EV [에뮬]+[실 API] | 부산 · 가족 | "충전하러 서야 해요"(범위 · 추정) | 휴게소 S 를 경유지로 | 경유지 목록 재조회 |

## 상태별 문장 (금지 문구 포함)

| 상태 | 쓴다 | 쓰지 않는다 |
|---|---|---|
| 약속 시간 없음 | "약속 시간을 알려 주시면 도착 여유를 확인해요" | "늦을 수 있어요" |
| 남은 시간 없음 | "내비 예상 시간을 받지 못했어요" | 우리가 계산한 ETA |
| 주차 대수 STALE | "운영 중 · 실시간 대수 확인 안 됨" | 대수 숫자 |
| 좌표 없음 | (후보에서 뺌) | 추측 위치 |
| 도보 시간 | 사용자가 정한 여유 "주차 후 10분 여유(설정값)" | 계산한 도보 분 |

## 주행 중 (DO)

한 줄 상태 + 음성 — "P1 주차장 · 14:05 기준 여유 있음" / "계획대로 가고 있어요". 비교·대안·설정 없음. 새 추천이 생기면 "정차하면 보여 드릴게요".
