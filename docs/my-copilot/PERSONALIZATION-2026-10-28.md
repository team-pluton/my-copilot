## 1. 개인화 차이 — 아빠+가족 / 엄마+가족 / 혼자 / 부부 / 업무 이동 (시연 데이터)

## 2. 자동으로 기억 가능한 것 / 기억할 수 없는 것

| 자동으로 기억(관찰 → 후보 → 한 번 확인) | 기억할 수 없음(사용자가 고르거나, 미지원) |
|---|---|
| 공조 설정 온도 · 공조 ON/OFF — HVAC 조회가 되는 차(설정 온도 조회·변경 콜백은 에뮬레이터 확인, ON/OFF 는 문서만) | **누가 운전하는가** — 운전자 프로필·디지털 키 API 없음 → 수동 |
| 운전석 통풍·열선 — Seat 조회가 되는 차(조회·변경 콜백은 에뮬레이터 확인 2026-10-29) | **누가 함께 탔는가** — 동승자 자동 감지 안 함(착석 감지 API 는 쓰지 않음) |
| 방문 중 · 귀가 등 여정 상태(Journey Memory) | 음악 취향 — 미디어 앱 상태 접근 미확인 |
| 마지막 운전자 · 탑승 조합(사용자가 고른 것) | 실내 조명 분위기 — 조회 경로 미확인(스위치뿐) |
| | 시트 위치·미러 — 차량 운전자 프로필이 한다 |

**학습 규칙**(`learning.ts` ↔ `Learning.kt` — 정확성 보정 2026-10-29, 9절): 출처가 VEHICLE(실차 콜백) 또는 MOCK(시연 조작판·개발 패널)인 변화만 기록 · 앱이 스스로 적용한 값(APP)·받은 적 없음(NONE)은 기록 안 함 · 운전자 미확인이면 기록 안 함 · 같은 **주인** 아래에서 **다른 이동 3번** 같은 값이어야 후보 · 값이 흔들리면 처음부터 · 후보는 **하나만, 한 번만** 묻는다("최근 3번 이동에서 혼자일 때 공조 온도가 24°C였어요 — 탑승 조합 취향으로 저장할까요?") · 거절한 값은 다시 묻지 않음(다른 값이 반복되면 새 후보) · 저장하면 주인(운전자 / 탑승 조합)에게.
**귀속**: 변경 주체는 SDK 콜백에 없다 → 운전석 항목(통풍·열선·핸들 열선)은 **혼자 탈 때만** 운전자에게(추정) 기록하고, 가족·부부 탑승 중의 시트 변경은 **기록하지 않는다**(조수석이 켰을 수 있다). 공조·전원은 "그 탑승 조합에서 쓰인 값"으로 조합에 기록한다 — 가족 공조는 아빠가 운전하든 엄마가 운전하든 같은 가족 기록, 혼자 공조는 운전자 × 혼자 — **저장도 같은 키로** `vault.soloCabin[운전자|모드]`(운전자별)에 한다(프로필 `targetC` 는 운전자 공유라 거기 쓰면 섞인다 — V21 검토 ②로 발견·수정). 저장은 어느 쪽이든 사용자 확인 뒤.
**증거 등급**: MOCK 관찰은 기록되지만 후보 문장 앞에 "시연 데이터 · "가 붙고 `realEvidence()`(VEHICLE 만) 집계에서 빠진다. MOCK 은 VEHICLE 기록을 덮지 못하고, VEHICLE 이 오면 MOCK 기록은 버린다. **실차 학습 증거는 0건** — VEHICLE 관찰은 어댑터의 HVAC·시트 콜백이 `Intent.LiveCabin` 으로 넣는다(2026-10-29 에뮬레이터에서 콜백 확인). 에뮬레이터 콜백도 코드상 VEHICLE 로 들어오지만 보고서에는 "에뮬레이터 콜백"이라 적고 실차 증거라 쓰지 않는다. 앱이 스스로 적용한 값의 재조회는 APP 으로 걸러 세지 않는다(테스트).
**하지 않는 것**(`LEARNING_LIMITS`): 계절·외기온 등 **조건별 취향 학습은 미구현** — 3번 반복한 값은 그 조합의 최근 값일 뿐, 모든 날씨·상황의 취향이라고 주장하지 않는다(여름 24°C 세 번이 겨울 취향은 아니다). 혼자 탈 때도 변경 주체는 **추정**(`DRIVER_ASSUMED`)이지 확정이 아니다 — 후보는 관찰한 값만 말하고 저장은 사용자 확인 뒤. 후보 카드 밑에 한 줄: "최근 이동의 값만 봅니다 · 계절·외기온은 고려하지 않음 · 누가 바꿨는지는 SDK 가 알려 주지 않음".
웹 시뮬레이터의 조작판 슬라이더·시트 토글과 차량용 앱의 개발 패널이 "차에서 누군가 돌린 것을 콜백이 알려 준 상황"을 연기한다(출처 **MOCK**). 실제 앱에서는 HVAC·Seat 콜백이 VEHICLE 로 이 자리에 온다 — 어댑터 배선 완료(`PleosCabinStateSource` → `Intent.LiveCabin`, 에뮬레이터에서 콘솔 변경이 준비 카드에 반영되는 것까지 확인). 3번 이동을 반복해 후보 카드가 뜨는 장면은 에뮬레이터에서 **미재현**(HANDOFF ⑥).
