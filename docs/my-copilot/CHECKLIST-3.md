## P0

### P0-1 앱 창 레이아웃
- [x] 화면 모드 이름: **기본 앱 창(세로 · 840×1184)** · **확장 앱 창(가로 · 1700×1184)** — 공식 레이아웃 문서의 값(research 7절). 전체 차량 셸은 "발표용 Mock".
- [x] 웹 홈·출발 준비·에너지: 확장 앱 창에서 왼쪽 = 상태·주요 행동, 오른쪽 = 준비 결과·판단 근거·출처. 본문을 가로로 늘리지 않는다.
- [x] 차량용 앱: 같은 배치(이미 오른쪽 열) · 작은 창(12.9" 세로 628×855dp)과 14.6" 가로(1360×948dp) Robolectric 캡처 · 실행 중 창 크기 바꿔도 이동 상태 유지(테스트 — 액티비티를 다시 만들어도 ViewModel 이 지킨다).
- 완료 조건: 4가지 창 크기 캡처에서 잘림 · 겹침 없음(눈으로 확인한 표) · 크기 변경 테스트 통과.

### P0-2 주행 중 화면
- [x] 순수 함수 `driveLine` — `QUIET`(판단 문제 없음 · 경유지까지 거리) · `ATTENTION`(충전 계획 확인 필요 — 짧게, 상세는 정차 후) · `UNKNOWN`(차량 정보 없음 — 지난 판단을 반복하지 않음).
- [x] QUIET 는 작은 글씨 한 줄 · 큰 숫자는 경유지 거리만 · 빨강·경고 아이콘 없음(제조사 경고처럼 보이지 않게).
- [x] 음성은 ATTENTION 으로 바뀔 때 한 번. QUIET 에서는 말하지 않는다.
- 완료 조건: TS·Kotlin 같은 표 테스트 · 웹·차량용 앱 주행 화면 캡처 3종.

### P0-3 에너지 문구
- [x] `energyView` 에 문맥(편도/왕복 · 경유지 포함) — 머리말:
  편도 충분 "충전 없이 도착할 수 있을 것으로 예상돼요" · 왕복 충분 "충전 없이 왕복할 수 있을 것으로 예상돼요" ·
  경유지 포함 "선택한 충전 경유지를 포함하면 계획을 마칠 수 있을 것으로 예상돼요" · 평균은 되고 비관은 모자람 "현재 조건에서는 충분할 수 있지만 여유가 크지 않아요" ·
  평균도 모자람 "충전 없이는 모자랄 수 있어요" · 범위 전체가 모자람 "충전 계획이 필요해요" · 모름 "최신 차량 정보가 없어 계획을 확인할 수 없어요".
- [x] 보조 줄에 기준을 적는다: "최소 잔량 20% 남기고 · 비관 추정까지(추정)".
- [x] 경유지를 골랐으면 그곳에서 80% 충전한 계획으로 다시 판단한다(옵션 계산과 같은 식).
- [x] 테스트: 배터리 5~100% · 편도/왕복 · 대기 유형 전 조합에서 "비관 추정이 모자라면 머리말에 '충분'·'예상돼요'가 없다".

### P0-4 출발 준비 상태
- [x] 상태 다섯: 확인 완료 · 확인 필요 · 이번에는 건너뜀 · 지원하지 않음 · 해당 없음.
- [x] 홈의 "이번에는 건너뛰기"(공조) → 건너뜀으로 기록(지금은 "그대로 두기"로 기록 — 잘못). 출발 준비 화면의 "지금 그대로 두기"만 확인 완료.
- [x] 준비물 · 충전 계획에도 "이번에는 건너뛰기". 건너뛴 것은 남은 일이 아니지만 완료도 아니다 — 요약에 따로.
- [x] 화면을 열거나 버튼을 눌렀다는 것만으로 완료가 되지 않는다(공조는 콜백 검증 · 준비물은 사용자 체크 · 충전은 경유지 콜백).
- 완료 조건: TS·Kotlin 테스트(건너뜀 ≠ 완료 · 방문 ≠ 완료) · C·A 장면 그대로.
