# 웹 시뮬레이터 ↔ Pleos 차량용 앱 — 같은 판단인가 (2026-10-26)

Pleos Connect 가 Android Automotive OS 기반이라 Kotlin · Compose 로 만든다.

| 결과물 | 역할 | 판단 코드 |
|---|---|---|

## 실차 입력은 Kotlin 전용 (2026-10-29)

`Intent.LiveSignals`(AAOS) · `Intent.LiveVehicle`(EvBattery) · **`Intent.LiveCabin`**(HVAC·Door, 에뮬레이터에서 처음 확인) 은 차량 어댑터가 넣는 입력이라 TS 거울이 없다 — 웹 시뮬레이터는 조작판(MOCK)으로 같은 자리를 연기한다. 판단 규칙(cabin · situation · learning)은 양쪽 같다.

실내 **제어**의 경계 `CabinControl`(Cabin.kt)과 그 구현 `PleosCabinControl`(copilot-adapters)도 Kotlin 전용이다 — 2026-10-29 에뮬레이터에서 `CONTROL_*` 가 normal 등급임을 확인한 뒤 만들었다. 세션의 `Intent.CabinResults` 에 `source: ControlSource`(기본 MOCK)가 생겼고, TS `settleCabin(…, source)` 는 이미 같은 인자를 받고 있어 규칙은 같다. `CabinState` 의 시트 단계(`seatVentLevel`·`seatHeatLevel`)와 해석 `SignalMapping.seatVentOn/seatHeatOn` 은 실차 입력이라 TS 거울 없음. `SdkStatus.EMULATOR_VERIFIED` 는 양쪽에 같이 넣었다(공조 온도·통풍시트).
