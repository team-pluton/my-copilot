## 두 제품

- **제품 X / 제품 Y** 로만 부른다. 어느 쪽이 X 인지는 **평가자마다 바꾼다**(1번 X=쉼표 DRIVE, 2번 X=MY CO-PILOT, …). 진행자만 대응표를 안다.
- 쉼표 DRIVE: `http://localhost:3008/demo` · MY CO-PILOT: `http://localhost:3008/copilot`. 둘 다 **셸 전체 보기 · 세로 · 다크**로 시작한다. 조작판(시뮬레이터 아래)은 가린다 — 평가자는 앱 창만 쓴다.
- 화면 상단의 제품 이름(쉼표 DRIVE / MY CO-PILOT · GNB 아이콘)은 진행자가 가리거나(브라우저 확대·창 크기) 미리 말하지 않는다. 가릴 수 없으면 "이름은 신경 쓰지 마세요"라고만 한다.
- 둘 다 차량 값은 모의다. 같은 말로 알린다: **"두 시연의 차량 값은 모의입니다. 실제 차량 연결은 이 웹 시연에는 없습니다."** (차량용 앱의 에뮬레이터 확인 결과는 평가 대상이 아니라 말하지 않는다 — 두 제품을 같은 조건으로)

## 순서

1. 안내(2분) — 목적("차 안에서 쓰는 앱 두 개를 비교합니다"), 녹화·기록 동의, 실명을 쓰지 않는다는 것.
2. 제품 X **첫 화면 10초** → "이 앱이 무엇을 해 주는 것 같나요?" 한 문장 기록(이해도).
3. 제품 X 공통 과제 1~3 (TASKS.md) — 과제마다 진행자 도구에서 시작/성공/포기. 도움은 요청받을 때만, 횟수 기록.
4. 제품 X 판단 신뢰도 질문 · 사용 의향 질문.
5. 제품 Y — 2~4 반복.
6. MY CO-PILOT 고유 과제(추가 가치) — **제품 이름을 밝히지 않은 채** "이 제품에만 있는 기능입니다"라고만 하고 진행. 비교 점수에 섞지 않는다.
7. 마무리 — "하나만 고른다면 어느 쪽, 왜?" 한 문장.

전체 40분 이내. 평가자 1명당 기록표 1장(RECORD.md) + 진행자 도구 JSON 1개.

## 공정성

- 두 제품의 기능 범위가 다르다. **공통 과제만 직접 비교**하고, MY CO-PILOT 에만 있는 것(출발 준비 · 하차 확인 · 프로필)은 추가 가치 항목으로 분리한다.
- 같은 과제를 두 번 하면 두 번째가 유리하다 — 순서 교차로 상쇄하되, 보고서에 "순서 효과 가능"을 적는다.
- 진행자가 두 제품 개발자다. 과제 설명은 **스크립트 그대로 읽는다**(TASKS.md 굵은 글).

## 집계

- 성공률·시간·탭 수는 과제별 표로. n 이 5 이하이므로 "경향"이라고만 쓴다.
