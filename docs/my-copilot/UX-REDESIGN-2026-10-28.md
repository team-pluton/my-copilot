## 5. 자동 판단 / 사용자 승인 / 수동 처리

| 구분 | 무엇 |
|---|---|
| **자동 판단**(사용자 조작 없음) | 저장 취향 읽기 · 차량 지원·권한·신선도 확인 · 현재 설정과 비교 · 같은 것 제외 · 적용 후보 묶기 · 여정 단계 추적 · 에너지 판단 · 제안 하나 고르기 · 지난번 조합 기억 |
| **사용자 승인**(탭 하나) | 탑승 조합 선택 · "N개 한 번에 적용" / "지금 그대로" · "모두 챙겼어요" · 경유지 추가 · 하차 확인 · 대기 유형 |
| **수동 처리**(앱이 하지 않음) | 지원 안 함·권한 없음·값 모름 항목("차량에서 직접") · 실내 조명(조회·제어 미확인) · 핸들 열선(미확인) · 음악 재생(기억만) · 주행 중 모든 설정 변경 · 원격 준비 |

자동 **제어**는 없다 — 제어는 권한 + 승인 + 정차를 다 만족할 때만, 실행 직전 재검사 뒤에 보낸다. 적용 결과는 항목마다 독립(적용 확인 · 거절 · 값 불일치 · 확인 못 함)이고, 확인 전에는 '적용 완료'라 쓰지 않는다. 지원되지 않는 항목 때문에 전체가 실패하지 않는다(테스트).

## 8. 실제 차량 적용을 막는 미해결 사항

1. **서드파티에 `CONTROL_CAR_CLIMATE` · `CONTROL_CAR_SEATS` 가 허용되는가** — 설명회 질문 10. 에뮬레이터 이미지에서는 normal 등급(선언만으로 허용, 2026-10-29) — 실차·App Market 은 그대로 미확인. 안 되면 준비 카드는 "차량에서 직접"만 남는다(그래도 비교·안내는 된다).
2. ~~시트~~ 조명 **조회** API 와 값 범위 — 시트는 어댑터가 읽고 단계 인코딩도 실측했다(E19 ✅, 2026-10-29). 조명(`Light`)은 그대로 미실행.
3. 음악 — 미디어 앱 플레이리스트를 고르고 재생하는 공식 경로(AAOS MediaSession 으로 충분한가) 미확인. 플레이어는 만들지 않는다.
4. 원격 준비 — 공개 SDK 경로 없음(마이현대·블루링크 영역). `RemotePrepareGateway` 는 NOT_AVAILABLE 고정.
5. 동력원 판별 — capability 기반 가설(E18).
6. 에뮬레이터 실행 자체(E1~E19) — 다른 PC.

## 10. 지난번 선택의 자동 적용 — 한 가지 판단

지시는 "같은 상황이면 선택 화면조차 생략할 수 있도록"이다. 구현은 **"지난번처럼 · 업무 이동" 한 번의 탭**까지다 — 공용 차량에서 지난 사람의 조합이 자동으로 켜지는 것을 피하려고(동승자 수동 설정 정책과 같은 결). 완전 자동(0 탭)은 `chooseAndPrepare(vault.lastMode)` 를 앱 시작에서 한 번 부르면 된다 — 디지털 키로 운전자가 확인되는 차량이면 그때 켜는 것이 맞다(현대차 프로필 자동 적용과 같은 조건).
