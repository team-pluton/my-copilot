# B안 조사 — 업무 일정 + 주차 + 내비 (2026-11-10, 조사만 · 구현 없음)

> 오너 지시(2026-11-09): B 는 **장기 핵심 서비스 후보**다. 공식 API · 접근 권한 · 데이터 품질 조사부터, 아직 구현하지 않는다.
> 근거 표기: **[공식]** 제공처 페이지·문서를 직접 읽음 · **[검색]** 검색 결과 요약만 봄(원문 미확인) · **[에뮬]** 에뮬레이터 실측 · **[미확인]**.

## 결론

1. **주차는 "위치·운영정보"부터는 된다.** 전국 정적 데이터(위치 · 운영시간 · 요금)는 공공 표준데이터로 받을 수 있고, 오너가 허용한 범위("주차장 위치·운영정보 조회")와 맞는다. **전국 실시간 빈자리는 공공 API 를 찾지 못했다** — 서울 등 일부 지자체와 공항만 있다 [검색].
2. **일정은 차 안에서 가져올 공식 경로가 아직 없다.** 에뮬레이터 이미지의 앱 라이브러리에 일정 앱이 없다 [에뮬, research 13절]. AAOS 참조 일정 앱은 제조사 폰 앱(companion) 또는 일정 제공자와 동기화하는 구조다 [검색 — Google Design for Driving]. Pleos 에 그 경로가 있는지 모른다 [미확인].
3. 그래서 B 의 첫 형태는 **"사용자가 고른 방문(시각 · 목적지) + 주차 정적 데이터 + 내비"** 가 현실적이다. 일정 자동 연동은 Pleos 의 공식 경로가 확인될 때까지 주장하지 않는다.

## 2. 일정

| 경로 | 상태 |
|---|---|
| Pleos Connect 기본 앱 | 에뮬레이터 이미지의 앱 9개에 일정 앱 없음 [에뮬, 2026-10-30] |
| Pleos 공개 SDK | 일정 API 없음 — 공개 SDK 에 운전자 프로필·디지털 키·미디어 API 도 없었다 [AAR, research 11절] |
| AAOS 참조 일정 앱 | 제조사 companion 앱 또는 표준 일정 제공자와 동기화 [검색 — developers.google.com/cars/design/automotive-os/apps/calendar] |
| AAOS `CalendarContract` 제공자 | 에뮬레이터에 일정 제공자가 있는지 **미확인** — `adb shell content query --uri content://com.android.calendar/calendars` 로 볼 수 있다(다음 에뮬레이터 실행 때) |
| 휴대폰 연동(마이현대 등) | 현대차 영역 · 서드파티 공개 경로 미확인 |

## 3. B 첫 형태(안) — 구현은 1차 제출 뒤, 관문 통과 후

"오후 3시 고객사 미팅"을 **사용자가 고른다**(방문 시각 · 목적지) → 목적지 주변 주차장(정적: 운영시간 · 요금, 서울은 실시간 빈자리) → 출발 시각 제안 → 승인 → 내비(목적지 또는 주차장을 경유지로) → 재조회 확인.
일정 앱 자동 연동은 하지 않는다고 분명히 쓴다.

## 4. 관문 (구현 전에 확인)

| # | 확인 | 방법 |
|---|---|---|
| B1 | 전국주차장정보표준데이터의 필드 · 갱신 주기 · 좌표 품질 | 공공데이터포털 원문 · 파일 내려받아 표본 검사 |
| B2 | 실시간 주차 API(서울 · 공항)의 활용 신청 · 응답 · 신선도 | 키 발급 뒤 실호출 |
| B3 | 에뮬레이터에 일정 제공자가 있는가 | `content query` |
| B4 | 내비 도착 예정 시각(ETA)을 앱이 받을 수 있는가 | NaviHelper `remainTime` · `requestTrip` 실측(이미 일부 [에뮬]) |

A안(픽업 + 날씨·교통)의 ETA 확인(B4)과 겹치므로 A 를 먼저 하면 B 의 관문 하나가 같이 풀린다.
