# 반드시 해결해야 할 위험 셋

## ① SDK·데이터 접근 제한 — **가장 크고 가장 급하다**

"추천 장소를 내비게이션 경유지로 꽂아 준다"가 이 앱의 핵심 주장이다.
그게 안 되면 **기획 전체가 그냥 휴게소 검색 앱**이 된다.

→ 다른 무엇보다 먼저 **경유지 추가 한 번을 성공시킨다.** 화면도 UI 도 없이
버튼 하나로 호출 → 콜백 확인까지만. 되면 기획서에 "검증 완료"로 쓸 수 있고,
안 되면 11/15 전에 기획을 틀 시간이 남는다.

지금 미확인인 것: `addWaypoint()` 존재와 시그니처 · 경유지 슬롯 개수 ·
Fused Location 제공 여부 · Vehicle API 권한. (`docs/04-architecture.md`)

## ② 단순 휴게소 추천 앱처럼 보일 위험

주행 타이머 + 장소 검색을 합친 것으로만 보이면 차별성이 없다.

→ **추천 이유를 화면에 쓴다** ("요청한 시설 2개 중 2개 충족 · 경로에서 1.2km").
→ 시연의 하이라이트를 추천 카드가 아니라 **선택한 장소가 내비게이션 경유지로
   실제 반영되는 장면**에 둔다.

## ③ 기존 내비게이션 기능과 겹칠 위험

이미 내비게이션에 휴게소 검색이 있다. "우리는 뭐가 다른가"에 한 문장으로
답할 수 있어야 한다.

→ 답: **기존은 "어디에 휴게소가 있나"를 답하고, 우리는 "지금 쉬어야 하나,
   쉰다면 어디가 맞나"를 답한다.** 주행 시간·동승 조건·시설 요구·경로 이탈을
   함께 보는 것이 그 차이다.
